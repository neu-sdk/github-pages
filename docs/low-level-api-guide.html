ExBrain SDK Low-Level API 解説書

はじめに

この文書は、プログラミングや脳機能計測の専門知識がない方でも、ExBrain SDK のLow-Level APIが 何をしているのか／どうやって実現しているのか を 理解できるように、平易な言葉で解説するものです。

ExBrain SDK は、NeU 製の小型脳活動センサ（額に装着する HOT-2000 や XB-01 など）を パソコンから操作するための「部品集」です。Low-Level APIは、その中でも センサとの通信・データの受け取り・数値への変換 という、最も土台になる部分を担当します。

1. このセンサは何を測っているのか

額に当たる部分に、赤外線に近い光を出す「光源」と、戻ってきた光を受け取る 「受光素子（フォトダイオード、略して PD）」が並んでいます。

  • 光は皮膚や頭蓋骨を通って脳の表面（前頭前野）まで届き、一部が戻ってきます。
  • 血液中のヘモグロビンは、この光を吸収します。
  • 脳が活発に働くと血流が増え、ヘモグロビンの量が変わる ため、 戻ってくる光の量も変わります。その量は、ヘモグロビン濃度と光路長（光が辿った距離）の積の変化量（dTHbL）に比例します。 （計測原理上、ヘモグロビン濃度の絶対値を求めることはできません。）

センサは左右それぞれに、光源から 1cm 離れた受光素子 と 3cm 離れた受光素子 を持っています。近い方（1cm）は主に皮膚表面の血流を、遠い方（3cm）は より深い脳の血流を反映します。「3cm の信号 − 1cm の信号」 を計算して表面の影響を差し引き、 さらに脈拍や呼吸による変動を取り除いて 脳活動の指標（ブレインインデックス） を求めます。

この「光の戻り量」から「ヘモグロビン濃度×光路長の変化量（dTHbL）」を計算し、さらに「脳活動の指標」や 「脈拍数」を求めるのが、低レベル層の中心的な仕事です。

2. 全体の流れ

Low-Level APIを使うと、おおむね次の順序で処理が進みます。

  ① センサを探す（探索）
        ↓
  ② センサにつなぐ（接続）
        ↓
  ③ 装着の具合を整える（装着調整）
        ↓
  ④ 基準値を取る（キャリブレーション）
        ↓
  ⑤ 測る（計測）── データがどんどん届く
        ↓
  ⑥ 終わる（切断）

それぞれの段階を順に見ていきます。

3. 各機能のしくみ

3.1 センサを探す（デバイス探索）

パソコンの近くにあるセンサを見つける機能です。USB ケーブルでつないだもの、 Bluetooth で過去にペア設定したもの、まだペア設定していないもの、を それぞれ対象にするか選べます。 [コード：探索条件は ExBrainSearchParameter の ShouldUSB / ShouldPairedBluetooth / ShouldNonPairedBluetooth（各 bool）で指定]

見つかったセンサは「追加されました」「情報が変わりました」「消えました」と いった**お知らせ（コールバック）**でアプリ側に随時伝えられます。 たくさんのセンサがある環境では、名前の一部（キーワード）で絞り込むこともできます。 [コード：絞り込みは ExBrainSearchParameter.Keywords（文字列配列、複数可）]

3.2 センサにつなぐ（接続）

探索で見つけたセンサを選んで接続します。接続すると、まずセンサから 機種・固有番号・ファームウェアの版・各種設定といった情報を読み取ります。

  • センサの古いファームウェア（2019 年 4 月版より前）は対応していないため、接続を中止します。
  • センサ本体が独自に脈拍計算などをする設定になっていると、SDK 側の処理と 二重になるため、接続時にその機能をオフにします。
  • 通信が突然切れても、設定によっては自動でつなぎ直します。 さらに、計測中に切れて再接続できた場合は、計測も自動で再開します。

接続中・計測中・切断中といった状態は、常にアプリ側へ通知されるので、 利用者に「いま何をしているか」を画面表示できます。

3.3 装着の具合を整える（装着調整 / ゲイン調整）

センサを額にどう当てているか（髪の量、肌の色、押し当て具合）によって、 戻ってくる光の強さは大きく変わります。光が弱すぎても強すぎても、 良いデータは取れません。

そこで、受光素子の増幅率（ゲイン）を自動で調整します。

  • 信号が弱すぎる（基準値より小さい）→ 増幅率を上げる
  • 信号が強すぎる（飽和している）→ 増幅率を下げる
  • ちょうど良くなるまで、少し変えては測り直す、を繰り返す

ちょうど良い範囲に収まったら、最後に目標値ぴったりへ微調整し、 もう一度確認して仕上げます。何度繰り返しても収まらない場合は 「これ以上調整できません」とエラーで知らせます。 通常、このエラーは装着状態を改善することで回避できます。 調整の経過はMGCParam.csv というファイルに記録することもできます。

このゲイン調整は、装着後に必ず実施してください。

3.4 基準値を取る（キャリブレーション）

人や装着状態によって、計測値には個人差の「下駄（ゲタ）」が乗っています。 計測開始の最初の十数秒（標準で約 12.8 秒）のあいだ静かにしてもらい、 その平均を**基準（ゼロ点）**として記録します。以降のデータからこの基準を 差し引くことで、変化分だけを正しく見られるようにします。

一度取った基準は使い回すことも、毎回取り直すこともできます。 [コード：計測開始時の recalibrate フラグ（false＝既存を再利用／true＝取り直し）]

3.5 測る（計測）

センサからは毎秒10 回、 次のような生データが届きます。

  • 4つの受光素子（HOT-2000 左右 × 1cm/3cm）の信号と飽和度 （XB-01は2つの受光素子）
  • 加速度・角速度（体の動き）
  • バッテリ残量・電圧

Low-Level APIは、これらがすべて揃ってから 1 件分のデータとして確定し、 以下の加工を施してアプリへ届けます。

  1. ヘモグロビン濃度に変換（光の戻り量を対数計算し、係数をかけて濃度に直す）
  2. 基準値を差し引く（キャリブレーション）
  3. ブレインインデックスを計算:（3cm − 1cm）の信号を平滑化（後述の「フィルタ」）
  4. 脈拍数を計算
  5. **脳活動度（カラーインデックス）**を計算
  6. 体動などによるノイズの有無を判定

計測データはアプリへ渡すと同時に、CSV ファイルへ保存することもできます。

3.6 ノイズの扱いと「フィルタ」

計測データには、まばたき・体の動き・電気的なゆらぎなど、さまざまな雑音が 混じります。これを和らげるのが「フィルタ」です。本 SDK では主に次を使います。

  • メディアンフィルタ：直近数件を小さい順に並べ、真ん中の値を採用する。 突発的なトゲ（外れ値）に強い。
  • 移動平均：直近数件の平均をとってなめらかにする。
  • 最大／最小フィルタ：直近数件の最大・最小を見る。値の暴れ具合の検出に使う。

たとえば、ある信号の一定期間の「直近の最大と最小の差」が大きすぎるときは、 体が動いたとみなしてNoiseDetectionFlagを付けます。

3.7 脈拍数の求め方

額のdHbTLデータには、**心臓の鼓動に合わせた細かな波（脈波）**が含まれています。 ここから脈拍数を割り出します。手順は次の通りです。

  1. 一定時間分（約 6.4 秒分）のデータをためる。
  2. 体が動いた区間は信頼できないので印を付け、近くの良い値で埋める。
  3. **周波数の分解（FFT）**という数学的な手法で、脈拍に相当する波（毎分 48〜180 回の範囲）だけを取り出す。
  4. 取り出した波が**プラスとマイナスを横切る回数（ゼロクロス）**を数え、 1 拍にかかる時間を逆算して 1 分あたりの拍数を求める。

複数の受光素子から別々に推定し、極端な値を避けるため中央寄りの値を採用します。

3.8 脳活動度（カラーインデックス）

「脳が活発／落ち着いている」を、おおまかな段階（メーター）で表す指標です。 ブレインインデックスが上がり続けているか／下がり続けているかの傾向を 時間をかけて集計し、急に跳ねないようゆっくり追従する数値として表現します。 一方向に偏りすぎた場合は自動的に中庸の値へ戻す仕組みも入っています。

3.9 その他

  • センサは、6軸の加速度計を持っていて、頭部の動きを表す加速度(Acc)と角加速度(Gyro)が送られてきます。 現在は、標準モード（１秒間に10回計測）のみに対応しています。
  • 脳活動量の変化の基準となる期間や、注目する期間を設定して、各計測データにマークを付けることができます。
  • 信号が振れすぎて正しい値が得られなかった場合に、Saturationフラグを付けます。
  • センサのバッテリー状態を取得します。

4. 「裏側で待たずに動く」しくみ

センサとの通信は、命令を送って返事を待つ、という往復が何度も発生します。 これを画面操作と同じスレッド（処理の流れ）で行うと、返事を待つあいだ アプリが固まってしまいます。

そこで本 SDK は、通信や計測やファイル保存を専用の裏方スレッドに任せ、 アプリ側は固まらずに動き続けられるようにしています。さらに、 「命令を送る → 返事を待つ → 次の命令」という一連の流れを、待ち時間に 他の処理を譲りながら順番にこなすタスク（コルーチン）という仕組みで 記述しています。これにより、複雑な手順を読みやすく・安全に実行できます。

複数の裏方スレッドが同じデータに同時に触れて壊さないよう、共有データには **鍵（排他制御）**をかけて、一度に 1 つの処理だけが触れるようにしています。

5. エラーと安全性

  • すべての操作は、成功・失敗を結果コード（例：成功、未接続、パラメータ不正、 ライセンスエラーなど）で返します。途中で異常が起きても、アプリ全体が 落ちないように設計されています。 [コード：EnmSdkResult（eSuccess＝成功 / eNotConnected＝未接続 / eParamWrong＝パラメータ不正 / eLicenseError＝ライセンスエラー など）]
  • 利用にはライセンスが必要で、無い場合はエラーで知らせます。
  • 接続を終えるときは、裏方スレッドの後始末を確実に行ってから、 ログファイルを閉じます。

6. まとめ

Low-Level APIは、脳活動センサとの**「会話」**を一手に引き受ける土台です。

  • センサを探し・つなぎ・装着を整え・基準を取り・測る、という一連を担う。
  • 光の戻り量をdTHbLへ、さらに脳活動の指標・脈拍・活動度へ変換する。
  • 雑音をフィルタで抑え、必要ならCSV 保存する。
  • すべてを裏方スレッドで処理し、アプリを固まらせない。

ここで作られた「きれいな計測データ」を受け取り、実験の進行管理や統計解析を行うのが、 上位の High-Level API です（別冊の High-Level API 解説書を参照）。
