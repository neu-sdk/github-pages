ExBrain SDK High-Level API 解説書

はじめに

この文書は、プログラミングや統計、脳機能計測の専門知識がない方でも、ExBrain SDK の 「High-Level API」が 何をしているのか／どうやって実現しているのか を 理解できるように、できるだけ平易に解説します。

Low-Level APIが「センサと会話してきれいな計測データを作る」土台だったのに対し、 **High-Level APIは「実験を進行させ、結果を統計的に分析する」**役割を担います。 脳活動の実験（たとえば「ある課題をやっているときと安静時で脳活動に差があるか？」）を 行う研究者・実験者を支える層です。

統計の部分は本 SDK の中でも特に専門性が高いところなので、 身近なたとえを交えて丁寧に説明します。

1. High-Level APIが実現することの全体像

  実験を組み立てる（Experiment / Block / MetaData）
        ↓
  測りながらリアルタイムに加工する（SMD）
        ↓
  ブロックごとにデータを整える（フィルタ・ベースライン補正）
        ↓
  集めたデータを統計で比較する（検定・条件間比較）

順番に見ていきます。

2. 実験を「ブロック」で組み立てる

心理・生理の実験は、ふつう同じ手順を何度も繰り返します。本 SDK では、 その 1 回分を 「ブロック」 と呼び、ブロックを 4 つの段階に分けて管理します。

  ① 事前ベースライン補正(preFitting)  … 課題前の安静・準備
  ② 課題(task)            … 計算問題を解く、など実際の課題
  ③ 安静(calmDown)        … 課題後の落ち着き時間
  ④ 事後ベースライン補正(postFitting) … 締めの安静

各段階を何秒にするかは「MetaData」というテンプレートで決めておきます。 あとは「ブロックを実行」と指示すれば、SDK が時間を計りながら自動で段階を進め、 それぞれの境目に**目印（マーカー）**をデータへ書き込みます。これにより、 あとから「ここからが課題区間」とはっきり区別できます。

複数のブロックには、被験者の識別子や繰り返し番号を付けられるので、 「誰の・何回目の・どの段階のデータか」を正確に管理できます。

3. 測りながら加工する（リアルタイム処理）

3.1 注目する量（関心量）

とくに注目するのは、「3cm の信号 − 1cm の信号」（dTHbL）です。Low-Level API 解説書で述べたとおり、 これは皮膚表面の影響を差し引いた、より脳に近い活動の指標です。

3.2 デジタルフィルタ（なめらかにする）

計測値には細かなゆらぎや、目的外の速い／遅い変動が混じります。 これを取り除くのが デジタルフィルタ です。本 SDK では Butterworth（バターワース）フィルタという、音響機器などでも広く使われる 定番のフィルタを用意しています。

  • ローパス：速すぎる変動（高周波の雑音）を削り、ゆっくりした本質的な変化を残す。
  • バンドパス：「速すぎる」「遅すぎる」の両方を削り、ちょうど見たい速さの変化だけを残す。

本 SDK では、ブロックの計測が終わった時点で、そのブロック全体にまとめてローパスフィルタをかけます。 しかも前向き・後ろ向きの二重がけを行うことで、「時間のずれ（位相の遅れ）が出ない」方式を 採用しています。これにより、波形の山や谷の位置がずれず、課題に対する反応のタイミングを 正確に保ったままなめらかにできます。

3.3 SMD（標準化平均差）── 「基準と比べてどれだけ違うか」

実験では、「ある基準の状態に比べて、いま脳活動がどれくらい変化したか」を 知りたいことがよくあります。これを数値化するのが SMD（標準化平均差） です。

身近なたとえで言うと——

あるクラスのテストで、A さんが 70 点を取りました。これは「良い」のでしょうか？ それはクラスの平均点とばらつきによります。平均 50 点・みんなの点が バラバラなクラスでの 70 点と、平均 68 点・みんな僅差のクラスでの 70 点とでは、 「目立ち具合」がまるで違います。

SMD は、この「ばらつきを物差しにした、目立ち具合」を表す数値です。 具体的には、

SMD ＝（いまの平均 − 基準の平均）÷ 全体のばらつき（標準偏差）

として計算します。割り算で「ばらつき」を物差しにしているので、 単位やスケールによらず公平に「効果の大きさ」を比べられるのが利点です。 （統計学では Cohen's d と呼ばれる考え方で、本 SDK ではサンプルが少ないときの 偏りを補正する工夫も入れています。）

ただし、生体信号は自己相関と呼ばれる自分自身との類似性が高いため、統計学で用いられる効果量より値が大きくなることに注意してください。 また、信号の立上りや立下りなど急峻な変化は「ばらつき」を大きくするため、SMDは減少する方向に働きます。

使い方は次のとおりです。

  1. まず 基準区間（リファレンス） を設定します（例：安静状態を一定時間記録）。 SDK はこの区間の平均とばらつきを覚えます。 [コード：開始は StartReferencePeriod(name)、確定は FinishReferencePeriod()]
  2. その後の計測では、直近の一定区間と基準区間を比べて SMD を計算し、 リアルタイムにアプリへ通知します。 [コード：「直近の一定区間」のフレーム数は Experiment 生成時の smdTargetWindowSize]

これにより、「いま、基準よりどれだけ脳活動が安定的に高まっているか」をその場で把握できます。

4. ブロックを整える（ベースライン補正）

ゆっくりした血液量変動のため、データ全体がゆっくり右肩上がり （または右肩下がり）に流れていくことがあります。これを「ドリフト（基線変動）」と呼びます。 ドリフトは、課題遂行以外の脳活動や全身性の血液量変化により発生します。 このまま課題区間を見ると、課題の効果なのかドリフトなのか区別できません。

そこで本 SDK は、課題の前後にある安静的な区間（事前ベースライン補正区間・事後ベースライン補正区間）に注目します。 この 2 区間は本来「課題遂行による脳活動変化が無い」はずなので、ここを結ぶまっすぐな傾きの線を 引いて「これがドリフトの正体」と推定し、ブロック全体からその傾きを差し引きます。

たとえるなら、傾いた机の上で測ったグラフを、机の傾きぶんだけ水平に直す作業です。 課題区間と課題終了後に血液が元にもどるまでの期間は傾きの推定に使わない点がポイントで、課題の効果を ドリフトと取り違えないようにしています。

5. 統計で比べる ── 「その差は意味があるのか？」

実験データが集まったら、いよいよ分析です。ここがHigh-Level APIの最も専門的な部分です。

5.1 そもそも「統計的に比べる」とは

たとえば「課題中の脳活動は安静時より高い」と言いたいとします。たまたま 高い値が出ただけかもしれません。「その差は、偶然では説明しにくいほど大きいか？」 を判断するのが統計的仮説検定です。

検定の結果は p 値（ピーチ） という数値で出ます。ざっくり言うと、

p 値 ＝「本当は差が無いのに、たまたまこれくらいの差が出てしまう確率」

です。p 値が小さい（慣習的に 0.05 未満）ほど、「偶然とは考えにくい ＝ 本物の差らしい」 と判断します。本 SDK の各検定は、この p 値を計算して返すのが役目です。

5.2 用意されている検定の種類

データの性質に応じて、適切な検定は変わります。本 SDK は主要な検定を揃えています。

検定 コード（C# 直接呼び出し） どんなときに使う（ざっくり）
Student の t 検定 Statistics.StudentT 2 グループの平均を比べる。データが釣鐘型で、ばらつきが同程度
Welch の t 検定 Statistics.WelchT 同上だが、2 グループのばらつきが違うとき
対応のある t 検定 Statistics.PairedT 同じ人の「前」と「後」など、ペアになったデータを比べる
Mann-Whitney U 検定 Statistics.MannWhitneyU 釣鐘型でなくてもよい。2 グループを順位で比べる
Wilcoxon 符号順位検定 Statistics.WilcoxonSignedRank ペアのデータを、釣鐘型を仮定せず順位で比べる
Shapiro-Wilk 検定 Statistics.ShapiroWilk データが釣鐘型（正規分布）かを調べる
Levene 検定 Statistics.Levene 2 グループのばらつきが同じかを調べる

ここで「釣鐘型（正規分布）」とは、平均の周りに山なりに分布する、自然界でよくある形の ことです。t 検定はこの形を前提にしますが、現実のデータがそうでないこともあります。 そのときは順位を使う Mann-Whitney / Wilcoxon（ノンパラメトリック検定）が頑健です。

5.3 「平均」ではなく「順位」で比べるとは

Mann-Whitney や Wilcoxon は、値そのものではなく順位を使います。たとえば 2 グループの数値を全部いっしょに小さい順に並べ、「グループ A は上位に固まっているか、 下位に固まっているか」を見ます。A が上位ばかりなら「A の方が大きい」と言えます。 外れ値（極端な値）に振り回されにくいのが長所です。

5.4 計算の中身（数学が好きな方向けの補足）

専門外の方は読み飛ばして構いませんが、内部では次のような数学的部品を使っています。

  • 正規分布・t 分布・F 分布の確率計算：これらの「確率の面積」を求めるために、 正則化不完全ベータ関数という関数を連分数という方法で精密に計算します。
  • 正規分布の逆計算（ある確率に対応する値を求める）には、有理式による高精度近似を使います。
  • Wilcoxon 検定では、データが少ないときはすべての可能な並び方を数え上げて 厳密な確率を出し、多いときは正規分布で近似します。さらに同じ値が複数あるとき （同順位）の補正も入れています。
  • Shapiro-Wilk 検定は、Royston という研究者が提案した近似式に基づいて、 データが釣鐘型からどれだけ外れているかを数値化します。

これらはいずれも、専用の統計ソフトと同等の結果を、SDK 単体で出すための実装です。

5.5 検定の自動選択

「どの検定を使えばいいか分からない」という方のために、本 SDK は 検定を自動で選ぶ機能を持っています。判断の流れは、統計の教科書どおりです。

  まず Shapiro-Wilk で「データは釣鐘型か？」を判定
        ├─ 釣鐘型でない → 順位の検定（Mann-Whitney / Wilcoxon）
        └─ 釣鐘型である → 次へ
                Levene で「2 グループのばらつきは同じか？」を判定
                    ├─ 同じ   → Student の t 検定
                    └─ 違う   → Welch の t 検定
        （同じ人のペアデータなら → 対応のある検定を選ぶ）

利用者は「お任せ（自動）」を選ぶだけで、データに合った妥当な検定が使われます。 [コード：比較関数の isParametric / isEqualVariance を未指定（C# では null）にすると自動判定] もちろん、検定を自分で指定することもできます。 [コード：isParametric / isEqualVariance に true/false を明示するか、 個別の検定関数（Statistics.WelchT など）を直接呼ぶ]

5.6 すぐ使える「条件間の比較」メニュー

実際の研究でよくある比較を、そのまま呼べる関数として用意しています。 利用者は細かい統計手続きを意識せず、目的に合うものを選ぶだけです。

比較メニュー コード（C# 関数） 何を比べるか
被験者内・課題間比較 TaskComparison.CompareWithinParticipantTasks 同じ人が行った2 種類の課題の脳活動を比べる
被験者内・事前事後比較 TaskComparison.CompareWithinParticipantPrePost 同じ人の訓練前と訓練後などを比べる
対応のある群課題比較 TaskComparison.ComparePairedGroupTasks ペア対応のある2 群を比べる
群間・課題比較 TaskComparison.CompareBetweenGroupsTask 別々の人からなる 2 グループを比べる
被験者間・課題比較 TaskComparison.CompareBetweenParticipantsTasks 異なる被験者集団どうしを比べる
課題対ベースライン比較 TaskComparison.CompareTaskAndBaseline 課題区間 と 事前安静区間を比べる（課題の効果を見る）

それぞれの比較では、正しい使い方を守っているかも自動でチェックします （例：「被験者内比較なのに別人のデータが混ざっていないか」「ペア比較なのに 数が合っているか」など）。間違いがあればエラーで知らせます。

結果は、「使った検定の種類」「p 値」「グループ間の差」が 返ります。左の計算でつまずいても右の計算は止まらないなど、頑丈な作りになっています。

6. 裏側の安全設計（簡単に）

  • 計測データは測りながら次々と書き足され、同時に分析側から参照されます。 この同時アクセスでデータが壊れないよう、**鍵（排他制御）**で守っています。
  • 各統計計算で異常（例：データが少なすぎる）が起きても、アプリ全体が落ちないよう、 エラーは数値や結果コードに変換して安全に返します。

7. まとめ

High-Level APIは、脳活動の実験そのものを支えるAPIです。

  • 実験をブロックと段階で組み立て、時間管理と目印付けを自動で行う。
  • 測りながらSMDで「基準からの変化」をその場で数値化する。
  • ブロックごとにフィルタ（位相のずれない二重がけ）でなめらかにし、ベースライン補正でドリフトを取り除く。
  • 集めたデータを、用途別の比較メニューと自動で選ばれる統計検定で分析し、 「その差に意味があるか（p 値）」を判定する。

これらにより、脳機能計測や統計の専門家でなくても、脳活動データから意味のある結論を 引き出せるよう設計されています。これまでは、計測後に解析を行うことが一般的でしたが、 本SDKを用いれば、計測途中に解析をして、その結果を後の計測に活かすというような、高度なアプリを簡単に作成できます。 土台となる計測のしくみについては、 別冊の Low-Level API 解説書 を参照してください。
