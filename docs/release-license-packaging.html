リリースライセンス パッケージングガイド

このページは、ExBrain SDK アプリをリリース向けに準備するアプリケーション開発者向けのドキュメントです。

重要なルール

リリースライセンスを作成する際は、ビルドフォルダーではなく、インストール済みのアプリのコピーを NeU License Manager で指定してください。

インストール済みフォルダーがお客様の実行環境です。ビルドフォルダーには余分なファイル、インストーラー出力の欠落、一時バイナリ、デバッグシンボル、または異なるレイアウトが含まれていることがよくあります。誤ったフォルダーを選択した場合、リリース SDK はアプリを AppInvalid として拒否する可能性があります。

リリースフロー

  1. アプリケーションをビルドします。
  2. お客様と同じように、ローカルでインストーラーを実行します。
  3. NeU License Manager を開きます。
  4. Create Release License を選択します。
  5. インストール済みアプリケーションフォルダー、またはインストール済みの EXE/スクリプトエントリポイントを選択します。
  6. 生成されたリリースパッケージファイルの保存先フォルダーを選択します。
  7. NeU License Manager はインストール済みファイルを確認し、ハッシュとアプリ検証 JSON の両方を含む AppHash ペイロードを作成します。
  8. ツールはその AppHash ペイロードを NeU ライセンスサーバーに送信します。
  9. サーバーはその AppHash ペイロードを含む署名済みリリースライセンスを返します。
  10. インストーラーを更新して、生成されたリリースライセンスをレジストリにインストールします。

このプロセスは、出荷するアプリケーションファイルを変更するたびに繰り返してください。

Python アプリ

Python アプリケーションの場合は、出荷するスクリプトとネイティブ依存関係が含まれるインストール済みフォルダーを選択するか、インストール済みエントリスクリプトを選択してください。

実行時は、インストール済みアプリフォルダーを作業ディレクトリとしてアプリを起動するか、そのアプリフォルダーに ExBrainSdkNative.dll を配置するか、SDK を読み込む前に NEU_APP_ROOT をインストール済みアプリフォルダーに設定してください。これにより、SDK が署名済みリリースライセンスにリストされたファイルをチェックするためのルートフォルダーが提供されます。

リリースアプリのチェックには次のようなファイルが含まれます：

  • .py、.pyw、.pyz
  • .pyd
  • .dll
  • パッケージデータファイル
  • アプリと一緒に出荷されるロック/設定/リソースファイル

__pycache__ や .pyc ファイルなどの生成されたキャッシュは除外されます。 log、logs、temp、または tmp という名前の一般的なトップレベルの可変フォルダーは除外されます。必要な出荷アセットをこれらのフォルダーに入れないでください。

生成ファイル

NeU License Manager は選択した出力フォルダーに次のファイルを書き込みます：

  • NeUReleaseLicense_<license-guid>_instructions_and_license.txt：バイリンガルのインストーラー手順とリリースライセンス。

この手順ファイルには完全なリリースライセンスが含まれています。インストーラーはそのライセンステキストを示されたとおりに正確に書き込む必要があります。

インストーラーのレジストリキー

エンドユーザー向けリリースビルドの場合は、マシン全体のレジストリ場所にリリースライセンスをインストールしてください：

HKLM\Software\NeU\Licenses

次の文字列値を作成します：

  • 値の名前：リリースライセンスの GUID
  • 値のデータ：手順ファイルの完全なリリースライセンステキスト

HKLM への書き込みには管理者権限が必要です。アプリ開発者はアプリケーションインストーラーからこの値を書き込む必要があります。

個別の JSON ファイルや個別の AppHash レジストリキーは不要です。アプリ検証 JSON は署名済みリリースライセンスに埋め込まれています。

NeU License Manager を通じてアクティベートされた開発者ライセンスは、引き続き HKCU\Software\NeU\Licenses にユーザーごとにインストールされます。SDK は HKCU と HKLM の両方を検索します。

AppInvalid が発生する原因

リリース SDK は次の場合にライセンスを AppInvalid として報告します：

  • 埋め込まれたアプリ検証 JSON が存在しない
  • 埋め込まれたアプリ検証 JSON の appHash が署名済み AppHash ペイロードハッシュと一致しない
  • 埋め込まれたアプリ検証 JSON が無効なスキーマに編集された
  • リストされたファイルが欠落している
  • リストされたファイルのサイズが異なる
  • リストされたファイルの SHA-256 コンテンツが異なる

SDK は AppHash を確認する前に一貫した内部表現を再構築するため、ホワイトスペースと JSON プロパティの順序は問題ありません。

オフライン動作

通常のリリース SDK 機能チェックはインターネットアクセスを必要としません。リリースライセンスは開発者やエンドユーザーのマシン ID に紐付けられていません。インストール済みアプリが署名済み AppHash と一致する場合にのみ、任意のマシンで有効です。

エンドユーザーのツールは後から再アクティベーションリクエストを送信することができます。これにより、エンドユーザーの PC をサーバーに表示させることができ、アプリまたはライセンスマネージャーがサーバーと同期を行う際に、リモートで失効したライセンスを検出できます。
